## 2. 알려진 약점과 Haru 의 대응

| 약점 | 대상 | Haru 대응 | 검증 |
|---|---|---|---|
| 처음에 메뉴가 복잡하다 | 트리플 | 한 화면의 "준비 체크리스트" + 도구 5개만 노출 | 화면 자동 점검 통과. 실제 사용자 반응은 미확인 |
| 등록 안 된 장소 추가가 어렵다 | 트리플 | 이름만 적으면 추가, 목록 붙여넣기 | 통과 |
| 날짜 간 이동이 불편·오류 | 트리플 | 버튼 한 번으로 전날/다음 날 이동, 시간 자동 배치 | 통과 |
| 없는 호텔·장소를 지어낸다 | Mindtrip | AI 장소는 여행 도시 좌표 범위 밖이면 버림, 샘플 호텔은 "예시" 표기 후 실제 검색으로 연결 | 좌표 검증은 단위 테스트 통과. 실제 AI 응답으로는 미검증 |
| 예산 등 조건을 무시한다 | Mindtrip | 요청 반영 내역(반영/미반영) 표시 + **일정 점검**(장소 수·긴 이동·시간 겹침·늦은 마무리·왕복 동선) + 시간 자동 맞춤 | 통과. 예산 초과 점검은 아직 없음 |
| 여행 중 모바일이 느리다 | Mindtrip | 지도 타일·서버 호출 없이 그리는 가벼운 화면 | 실기기 속도 측정 안 함 |
| 오프라인 불가 | Mindtrip | 일정·지도·짐·가계부를 기기에 저장 | 목업 모드 기준 통과 |
| 안드로이드 앱 없음 | Mindtrip | iOS·Android 동시 | 스토어 빌드 전 |

## 3. Haru 가 아직 못 하는 것 (정직한 격차)

1. **장소 데이터 규모** — Mindtrip 1,100만 곳, 트리플 235개 도시 가이드에 비해 Haru 의 검증된 장소·가이드는 매우 적다. 가장 큰 격차다.
2. **실시간 공동 편집** — 지금은 사본 전달이다. Supabase 연결 뒤 구현 가능.
3. **커뮤니티의 초기 공백** — 여행자 톡은 사람이 없으면 가치가 없다. 초기에 운영팀이 도시별 확인된 정보를 채워야 하고, 신고 처리 인력이 필요하다.
4. **앱 안 예약·가격 알림** — 링크 연결 모델이라 하지 않는다 (예약 대행 책임을 지지 않기 위한 선택).
5. **환율·번역·사진 여행기·사진/PDF 가져오기** — 미구현.
6. **이동 시간은 추정치** — 직선거리 기반이라 실제 경로와 다를 수 있다.

## 4. 차별점으로 밀 것

"하루 만에 준비 끝" — 일정 → 항공 → 숙소(나눠 묵기) → 날씨·옷차림 → 짐 → 공항 → 나라별 꿀팁 → 보고서까지 한 줄로 이어지는 준비 체크리스트. 두 플랫폼 모두 이 "준비 완료율" 관점은 없다.
