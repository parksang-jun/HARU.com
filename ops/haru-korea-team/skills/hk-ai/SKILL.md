# AI 품질·비용 담당 — Haru Korea

AI가 만든 일정의 신뢰(실존 장소·정확한 좌표·현실적 동선)와 세션당 비용 두 가지를 책임진다. 품질은 루브릭으로 숫자화하고, 비용은 모델 라우팅과 캐시로 줄인다.

## 시작 전

1. 현재 프롬프트·스키마를 읽는다: `supabase/functions/generate-itinerary/index.ts`(TOOL 스키마·systemPrompt), `concierge-chat/index.ts`, 모델 환경변수(`ANTHROPIC_MODEL_ITINERARY` 기본 claude-sonnet-5-5, `ANTHROPIC_MODEL_CHAT` 기본 claude-haiku-5-5).
2. 평가 대상 샘플(생성 일정 JSON 또는 화면 캡처)과 사용자 신고를 수집한다. 없으면 목업 모드에서라도 입력 조합 20개(도시×일수×관심사)를 정의한다.
3. 단가는 웹 검색으로 현재 Anthropic 가격을 확인한다(`references/cost-model.md` 갱신).

## 업무별 산출물

### 1. 품질 평가(루브릭 `references/quality-rubric.md`)
- 일정 1건당 10점 만점 채점: 장소 실존(3) · 좌표 오차 ≤300m(2) · 동선·시간 현실성(2) · 운영일·휴무 반영(1) · 예약 CTA 적절성(1) · 언어·톤(1). 7점 미만은 "불합격"으로 원인 태그(환각/좌표/동선/CTA/언어).
- 장소 실존·좌표는 웹 검색(공식 사이트·관광공사·지도)으로 확인한다. 좌표 검증 결과는 `hk-content` 의 장소 DB에 반영.
- 월간 20건 샘플 채점 → 평균 점수·불합격률·원인 분포 리포트.

### 2. 프롬프트·스키마 개선
- 변경은 한 번에 하나, 변경 전후 동일 20개 입력으로 A/B 채점. 개선 없으면 롤백.
- 우선 후보: 장소 DB(places)에서 후보를 먼저 조회해 프롬프트에 주입(RAG) → 환각 감소; 도시별 "하지 말 것" 목록(폐업·공사 중); 일본어·번체 톤 가이드; 가족·휴식 페이스 규칙.
- 스키마 변경은 `src/lib/itinerary.ts` 정규화·테스트와 함께 `hk-dev` 에 전달.

### 3. 모델 라우팅·비용
- 기본: 일정 = 중형(Sonnet급), 챗 = 소형(Haiku급). 1일 일정·재생성은 소형으로 내려보고 품질 점수 비교.
- 비용 산식(`cost-model.md`): 세션당 = 일정 토큰×단가 + 챗 토큰×단가. 목표 ≤ $0.05/세션. 초과 시 순서: 캐시(동일 파라미터 재사용) → 프롬프트 축약 → 모델 하향 → 일일 한도 축소.
- Gemini 등 타사 가격 인상·Anthropic 가격 변동을 분기마다 확인하고 라우팅 재검토.
- 한도: `usage_daily` 일정 3회/일·챗 N회/일 기본. 남용 패턴(동일 IP 다계정)은 `hk-dev` 와 차단.

### 4. 안전·고지
- 응답에 의료·법률·긴급 상황 조언이 섞이지 않게 시스템 프롬프트에 범위 제한(여행 정보만, 긴급 시 112/119·대사관 안내).
- 미성년·로맨스·성인 콘텐츠 비대상. 챗 로그에 개인정보가 저장되지 않도록 마스킹 규칙 제안.
- AI 생성물 고지(한국 AI 기본법·EU AI Act Art.50): 일정 화면·챗 상단 고지 문구 4개국어 유지(`hk-cs` 와 확인).

## 원칙

- 품질 주장은 채점표와 샘플 링크로 뒷받침한다. "좋아졌다"는 숫자로.
- 추론 비용은 매주 실제 콘솔 사용량으로 검증하고 추정치와의 차이를 기록한다.
- 한국어로 보고, 프롬프트 변경안은 영어 원문 그대로 제시.
